# Design Wheel — 意思決定記録（ADR）

## ADR-001: デリバリーツールの形態（2026-06-18 確定）

### 決定
Design Wheel を「非デザイナーが70%品質を出し、フィードバックで永久に質が上がるツール」に
するための形態を、**段階的に Web アプリへ**収束させる。即時に作り込まず、Project で1周回す。

```
[エンジン＝不変・git管理]
   パターン在庫(patterns/<p>/SYSTEM.md) + HTMLキャプチャ出力 + フィードバックログ
        ↑ 質の源泉。宮川が磨く真ソース
[インターフェース＝段階進化]
   段階1: claude.ai 共有 Project（v0・今すぐ）
   段階2: 薄い Web アプリ（段階1の痛点が分かってから）
   段階3: ログ駆動の改善（低評価パターンを自動炙り出し）
```

### 各形態の評価と結論
| 形態 | 質 | 非デザイナー | 更新 | FB収集 | 判定 |
|---|---|---|---|---|---|
| md/プロンプト共有 | △ | △ | × 各自分岐 | × | 却下（一時的） |
| Claude Skill | ◯ | ◯ | △ | × | v0繋ぎ可 |
| claude.ai Project | ◯ | ◎ | ◎ | △手動 | **v0 採用** |
| **Web アプリ** | ◎ | ◎ | ◎ 即全員 | ◎自動 | **長期本命** |
| デスクトップアプリ | ◎ | ◯ | △配布要 | ◎ | 不要（動画でない＝軽い） |
| Figma/Canvaプラグイン | × 翻訳ロス | ◯ | △ | △ | 却下 |
| Slack | × 制作面でない | ◎ | — | ◎ | **収集チャネルとして併用** |

### 根拠
- **質の源泉は出力方式**: Canva/Figma 再現は「翻訳ロス」で劣化。Claude が作る完成形 HTML を
  **そのまま画像書き出し（HTMLキャプチャ）**するのが最高品質。実証= `brand/fambox/banners/`（capture.sh）。
- **Web > デスクトップ**: 動画(Palmier)と違いデザインは軽い HTML。Web ならデプロイで全員即更新＝真にアプリ的。
- **作る前に1周回す**: sporty で「refs を見る前に作り込むと方向を外す」と学んだ（[[feedback_gather_refs_before_systematize_style]]）。
  Web アプリも同じ。Project v0 で実使用の痛点を取ってから作る。エンジンは不変なので段階移行で無駄が出ない。
- **参考**: Palmier（palmier.io）= 生成がキャンバス上にあり AI(MCP)が直接編集する動画エディタ。
  この**相互作用パラダイム（チャット→ライブプレビュー→書き出し）を Web で**再現するのが Design Wheel の理想形。

### 不変条件（インターフェースが変わっても守る）
1. 真ソース = `patterns/<p>/SYSTEM.md`（git）。各UIはこれを読むだけ。
2. 出力 = HTMLキャプチャ（翻訳ロスを作らない）。
3. ループ = 構造的フィードバック収集（使ったパターン/指示/評価/「難しかった点」）→ SYSTEM改善 → 再配布。
