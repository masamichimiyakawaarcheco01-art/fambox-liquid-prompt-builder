# FOUNDATIONS — 普遍の美（Layer ①）

> 出典: 宮川のUIデザイン教材「UIデザインの基本」全121ページを蒸留。
> **これは全パターン・全生成に共通で効く「骨格と作法」**。各 SYSTEM（色/フォント/世界観＝Layer ②）より下のレイヤーで、どのパターンでも必ず守る。
> SYSTEM の値と衝突したら **SYSTEM を優先**（FOUNDATIONS は土台、SYSTEM は意思）。

---

## 0. 作る順番（これを必ずこの順で）

教材の核心は「**スタイル（色・装飾）より先に、骨格を比率で整える**」こと。順番を守るだけで非デザイナーでも破綻しない。

1. **平面構成**：画面を整数比で分割する
2. **配置（余白）**：余白の大中小を等比で決め、ポリシーで割り当てる
3. **キャラクターライン**：アラインで「見えない線」を通し、構造を作る
4. **タイポグラフィ**：フォント種別とジャンプ率で雰囲気を載せ、意味と形を整える

> 「**しつこく整えるだけで、ある程度のデザイン品質は担保できる。明日から誰でもできる**」（教材原文の主張）。色や写真より、比率・余白・アラインが効く。

---

## 1. 平面構成 — 整数比で分割する

- レイアウトは **単純な整数比**（1:1 / 1:2 / 2:3 / 1:3 / Full）で分割する。中途半端な比率は使わない。
- 「**300px 決め打ち**」のような固定寸法でデザインしない。**寸法ではなく要素間の関係（比率）**を決める。
- 最も大きなコンテナの分割＝**アプリ/ページの構造設計そのもの**。例: 縦に2本線→段組、横帯→ヘッダー。
- 典型3分割: **赤＝ナビ / 黄＝グローバルヘッダー / 青＝ボディ**。まず「どう割れば美しいか」、次に「どの比率で割るか」。

---

## 2. 配置（余白）— 等比の大中小＋ポリシー

### 余白の決め方
- 余白は **等比（1.5倍 or 2倍）** で大中小を定義する。例: 20 / 30 / 45（1.5倍）、25 / 50 / 100（2倍）。
- **等差（10px刻み: 10/20/30…）は禁止**。「同じくらいだけど微妙に違う」＝最も雑に見える。差は2倍 or 半分で**ひと目で分かる**ように。
- 用語: **マージン＝オブジェクト間の距離 / パディング＝コンテナと内部オブジェクトの距離**。

### 割り当てポリシー（最重要）
- **存在意義が同じ余白は同じ寸法、異なるなら異なる寸法**。
- 要素の類似性・関係性・概念的ヒエラルキーの大小に応じて：
  - コンテナ ↔ 子要素（サムネイル等）の間 ＝ **大**
  - 兄弟要素どうしの間 ＝ **中**
  - 要素内の各オブジェクト間 ＝ **小**
- **裏技**: 迷ったら「全余白を共通の1サイズ・全隙間に同じ余白」にしてもよい。少し間延びするが整然と見え破綻しない。

---

## 3. キャラクターライン — アラインで見えない線を通す

- 「キャラクターライン」＝車のボディ側面の線のように、**デザインにメリハリと構造を与える線**。
- 線は引かなくてよい。**要素をアラインすれば、ユーザーの脳内で「見えない線」が補完される**。
- 強いキャラクターラインの条件: 境界のコントラスト / サイズ / **連続性（揃っている範囲が長いほど強い）**。
- オブジェクトのアラインがコンテナのアウトラインより強い線になることも → **余白定義の正確さがそのまま線の美しさになる**。
- 補強したいときは **飾りパーツ**（小さな四角・ラインなど）を端部に置くと線が強調される。
- **整列ツールの自動整列後は要注意**: テキストボックスはデフォルト余白を含むため、アラインし直す。

---

## 4. タイポグラフィ — 雰囲気・意味・形

### スタイルはまずフォントで決まる
- テキストはUIで最も頻出するオブジェクト。**最初に表現したい雰囲気を言語化 → font-family を決める**。これでデザインテイストが初めて載る。

### ジャンプ率（大小差）
- フォントサイズの**大小差が大きい＝ジャンプ率高＝躍動感**。**小さい＝ジャンプ率低＝整然・高級感**。
- 表現したい雰囲気に合わせて選ぶ（スポーツ＝高め、ラグジュアリー/コーポレート＝低め）。

### 意味と形の2側面
- **意味**: 強調したいものは**大きく・ハイコントラスト**（読んでも読まなくても成立）。補足情報は**小さく・ローコントラスト**（注意して読めば読める）。
- **形**: 文字を**矩形**として捉え、重要性を一旦忘れて**比率で美しく**配置する。意味上の重要度と、形（平面構成）上の重要度は別物（例: コンセプト文より "01" を大きく出す）。

### 行間・スケール
- **行間はテキストサイズの1:1以上をキープ**（≒75%を下回ると窮屈）。
- 6段階スケールを事前に決めて計画的に使う（毎回個別最適しない＝実装増・不調和）:
  | 段 | 用途 |
  |---|---|
  | 飾り | 装飾用の特大/特殊 |
  | Large | h1：ページ内に1つの大見出し |
  | Medium & Large | h2：小見出し |
  | Medium | h3：強調 |
  | **Medium & Small** | **body：最頻出** |
  | Small | 最小（≒最小余白と同寸） |

## 5. カラーの構造（モジュール標準）

色そのものは Layer ②（各 SYSTEM）が決めるが、**役割の構造は普遍**：

- **ブランド4色**: Primary / Secondary / Inactive（非活性） / Error
- **グレースケール4段**: Gray1〜Gray4
- チップ等: Secondary があれば Secondary、無ければ Primary。**暗い背景は白文字、明るい背景は黒文字**。
- スナックバー推奨背景 `#323232`、アクションは Primary。他色なら文字を白/黒で視認性確保。

---

## 6. コンポーネントの状態（普遍の標準）

インタラクティブ要素は**状態を必ずセットで設計**する：

`デフォルト / 押下時(Pressed) / ドラッグ時 / 選択後 / ディスエーブル`、フォーム系は `フォーカス / 入力後 / エラー` も。

- 押下時＝オーバーレイ（例: Secondary 不透明度10%重ね）。ディスエーブル＝Gray＋専用色。
- **テキストフィールド**: default / focus（枠が Primary）/ 入力後 / disable / **error（赤枠＋⚠️＋エラーメッセージ）**。
- **選択コントロールの使い分け**: 複数選択＝チェックボックス / 排他1択＝ラジオ / ON-OFF単体＝トグル（モバイル推奨）。
- **ボタン種別**: 塗り(Filled) / 線(Outlined) / テキストのみ / アイコン / トグル / ステップ。各state必須。
- **FAB**: 画面の主要1アクション。下部や端に置き、上に他要素を被せない。
- **カード**: 「印刷物」の概念。内容をはみ出させない。背景がスクロールする場面（地図上等）ではシャドウを付ける。
- **ダイアログ**: 最上層・他機能を無効化・上下左右中央。**ボタン2つなら「キャンセル＝弱/実行＝強」**の強弱を付ける。
- **スナックバー**: 一度に1つ・フッター上・一定時間で自動消滅。
- ナビゲーションドロワー / タブ / メニュー(ドロップダウン) / ツールチップ / スライダー / ステッパー / シート / 評価（星0.5刻み）も同じ作法（状態・整列・比率）で。

---

## 7. 制作のスピード設計（Lo→Mid→Hi）

非デザイナーが手戻りなく進めるための段階。Design Wheel は実質 Hi-Fi を一気に出すが、**指示が曖昧なときはこの順で考える**：

1. **Lo-Fi**: 画面の区分＋載せる機能リスト（何を・どこに）
2. **Mid-Fi**: モジュール/コンポーネント/構成要素のマップ＋ポンチ絵（どの部品を使うか）
3. **Hi-Fi**: 比率・余白・アライン・タイポを**数値で確定**（このFOUNDATIONS の1〜4を適用）

> アトミックデザイン: Atom→Molecule→Organism→Template→Page。Template を組むときは **Organism→Molecule→Atom の順**で内から詰める。

- [ ] 余白は**等比の大中小**で、**等差(10px刻み)になっていない**か
- [ ] 余白ポリシー（コンテナ-子=大 / 兄弟=中 / 要素内=小）に沿っているか
- [ ] 要素が**アラインして見えない線**が通っているか
- [ ] 見出し/本文の**ジャンプ率**が雰囲気に合っているか／**行間≥1:1**か
- [ ] 強調＝大・ハイコントラスト、補足＝小・ローコントラストになっているか
- [ ] インタラクティブ要素に**状態（最低 default/hover/disable）**があるか
- [ ] （SYSTEMの色・フォント・余白の値を**創作せず厳守**したか）
