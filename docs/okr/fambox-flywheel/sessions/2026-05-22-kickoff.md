# 2026-05-22 キックオフブレスト議事録

> プロジェクト開始日。Experience Flywheel 構想の確立と永続化基盤の構築。

参加：宮川 + Claude
所要：約 1セッション

## 議論の流れ

### 1. 出発点：宮川さんの問題提起

> 「デザイナーでなくても、ある程度 FAM BOX らしさが入った UI や広告紙、画像をメンバーが誰でも作れる仕組みを作りたい」
> 「早く・高品質に FAM BOX らしいアウトプットを出力するためにどんなシステムが必要か」

参考リンク：[Anima — Claude Design Review 日本語記事](https://www.animaapp.com/blog/ja/ai-design-ja/claude-design-review-features-pros-cons-and-best-alternatives-japanese/)

### 2. Claude の最初のフレーミング

3つのアプローチ案を提示：
- A. テンプレート配布型（Canva Brand Kit 中心）
- B. AI 主体型（Claude Project で生成）
- C. ブランドエンジン型（テンプレ + AI ハイブリッド、3フェーズ）

Claude 推奨：C をフェーズ分けで構築。

### 3. 宮川さんの構想転換（重要な転回点）

> 「少し異なる構想があります」

Experience Flywheel（添付画像：自律型経営のエンジン）を参考に提示：

- **Sense**：Shopify / ユーザー / SNS から良い・悪い数値を検知
- **Generate**：Brand DNA + DS を考慮してアウトプット生成
- **Reach**：サードパーティを活用して顧客提供
- **Learn**：Second Brain のように継続学習 → Sense へ戻す

さらに：

> 「他のブランドでもこのサイクルを提供できるようにしたい。
> そのためにデザインのパターンをライブラリとして持ち、ライブラリごとのDSを作る」

つまり：
1. FAMBOX で Flywheel を構築（短期）
2. 他ブランドへ展開可能なプラットフォーム化（長期）

### 4. Claude の評価

**正しい方向と判断した理由：**
- クローズドループ（Sense → Learn）は正しいパラダイム
- Brand DNA を制約として使う発想が秀逸
- Multi-brand 抽象化は productizable

**重要な発見：既に Sense と Learn は部分的に動いている**

| Flywheel 層 | 既存資産 | 状態 |
|---|---|---|
| Sense | Design Insight Engine（月曜08:03 自動）/ GA4 自動レポート | 🟢 部分稼働 |
| Generate | LPB v4.1 + DS v0.5 + bugs.md + Brand DNA | 🟢 高完成度 |
| Reach | Shopify / Seal / SNS（手動） | 🟡 手動運用 |
| Learn | brain/40_Bookmarks / sessions index | 🟡 取込のみ |

→ 「ホイールはあるが、繋がっていない」状態。

**3つの懸念：**
1. Sense → Generate の「データを意味に変える層」が最難関
2. Multi-brand 化は早すぎると死ぬ（FAMBOX 完成後）
3. 1人で作れる規模を超えている（AI を3人目として組み込めば可能）

**提案：最小ホイール（MVF）から始める**

### 5. 質疑のまとめ（Q&A）

| 質問 | 回答 |
|---|---|
| 最重要出力は？ | Shopify に関わらない Web UI（長期）、今は Shopify セクション（短期）|
| 想定ユーザーは？ | マレルチーム（松浦・三宅・深澤）SNS / マーケ担当、コードなし、Figma 基礎 |
| ツール環境は？ | Canva / Adobe CC / Claude / Figma すべてあり |
| 現状の痛みは？ | A（宮川さんがボトルネック）+ B（自己流逸脱）+ D（外注コスト）|
| ガバナンスは？ | 完全セルフ、レビューなし（ガードレールをシステムに埋める）|
| 方向性確認 | A：Sense と Learn を含めた本格 Flywheel 設計を続ける |

### 6. 永続化システムの構築決定

宮川さん：

> 「この構想を忘れたくない。私がいつでも確認でき、長期的に開発でき、あなたも進捗や途中で作業が切断されても続行できる状態にしたい」

→ Phase 0：永続化基盤を最優先で構築することに決定。

このディレクトリ自体がその成果物。

## 今日決まったこと（DECISIONS.md より抜粋）

- D-001：対象ユーザー = マレルチーム
- D-002：出力優先順位（Shopify セクション最重要、長期は非依存 Web UI）
- D-003：完全セルフ、レビューなし
- D-004：Experience Flywheel 構造採用
- D-005：最小ホイール（MVF）から始める
- D-006：Brand Layer と Engine Layer 完全分離
- D-007：DS は 4階層（tokens / components / patterns / templates）
- D-008：マルチブランド化は FAMBOX 1.0 後
- D-009：永続化システムを最初に構築
