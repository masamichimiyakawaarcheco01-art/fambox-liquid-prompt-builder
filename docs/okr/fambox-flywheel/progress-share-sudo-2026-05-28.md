## 📖 進捗ストーリー

### 1️⃣ 出発点：「私が事業のボトルネックになっている」

FAMBOX 関連のデザインが全部私を通る。
- マレルの SNS / 動画コンテンツのチェック
- 松浦さんの法人ページ改善
- 安原さんのレポート資料

→ これが **事業のスピード上限**。これを外したい。

### 2️⃣ ゴール設計：3段階で進める

目指すのは「**誰でも 7割の質のアウトプットを早く出せるインフラ**」。
Marc が右側（パンケーキ）でやっているのと同じ目標。違うのは領域だけ。

```
Step 1 (〜2026-07)  私個人のインフラ完成、10倍速で作れる
       ↓
Step 2 (〜2026-10)  皆さんが Slack で指示書を書くと数時間で初稿
       ↓
Step 3 (〜2027-Q1)  誰でも使える MVP 完成 = Flywheel 完成
```

須藤さんから先日教えてもらった「**3段階目から始めない**」を守って、Step 1 から積み上げています。

### 3️⃣ Marc に相談 → 1日でディープなレビュー獲得

構想を Marc に Slack で共有。**1日で具体的なフィードバックが返ってきた**。peer 関係が成立した瞬間。

**Marc が「このままでいい」と評価してくれたこと（3つ）：**

| 評価項目 | Marc のコメント |
|---|---|
| システムを Brand / Engine / Data の 3層に分離する設計 | 「excellent。自分の Archeco でも採用したい」|
| 意思決定を D-001, D-002... と連番で記録する仕組み | 「very solid。Marc の `EXTERNAL-INFLUENCES.md` に参考追加」|
| **bugs.md（失敗 → ルール化）** | 「**本当の学習はここで起きている**」と最重要視 |

### 4️⃣ Marc からの 5つの助言 → 全部今週中に反映済

ここが今週の中身です。Marc がくれた改善案を、その日のうちに全部プランに反映しました。

#### 助言 1：「70% / 30% パーセンテージ → 作業カテゴリで定義」

**なぜ大事：** 時間が経つと「70%」の意味が人によって変わって曖昧になる。

**私の対応：** AI と人間の境界を **4つのカテゴリ** で定義し直し。
- **AI proposes**（提案）：AI が下書きを出す
- **Human validates**（承認）：人間が OK/NG 判定
- **Human adjusts**（微調整）：人間が文脈合わせ
- **Human decides**（決定）：人間が複数案から選ぶ

→ Step 2/3 で皆さんが入ってきた時に、誰が何をやるかが明確に。

#### 助言 2：「Learn 層を Step 3 まで待たず Step 1 から守る」

**なぜ大事：** **「速くなるが学習しなくなる」リスク**。Generate（生成）が速くなると満足して、Learn（失敗から学ぶ）が止まる。

**私の対応：** Step 1 から最小機構を必須化。
- 失敗発生時 → bugs.md に即追加
- 同じ修正を2回説明したら → 即ルール化
- 月1回 bugs.md 追加件数を可視化
- **金曜事業開発の発表に「今週の Learn 進捗」を恒久項目化**

→ 来週から事業開発で毎週 Learn 進捗を報告します。

#### 助言 3：「DNA に『次バージョンへの進化条件』を明文化」

**なぜ大事：** 「確定した」と思った瞬間に文書が化石化する。

**私の対応：** Brand DNA v1.0 に **Evolution Triggers** セクションを追加。
- v1.1 トリガー：新 audience / 新 market / Verbal Identity 大改訂 等
- v2.0 トリガー：新 direction / マルチブランド化 / 事業モデル変更 等
- **半年に1回（1月・7月）に条件チェック**

→ DNA が現実と乖離する前に、計画的に進化させる。

#### 助言 4：「全判断基準を1ファイルに集約する CLAUDE.md を作る」

**なぜ大事：** 「**非デザイナーが入ってくる時の最大の課題は、ルールの質ではなく、すでに決まっていることの明確さ**」。Marc の予言「Q1 2027 前に作っておけば膨大な時間が節約できる」。

**私の対応：** `brand/fambox/CLAUDE.md` を **今週中に作成**（591行 / 11セクション）。
- Identity / Surfaces / Hard Rules / AI-Human Boundary / Vocabulary / Exclusions / Learn Loop / Onboarding Flow / テンプレ集

→ Step 2 で新メンバーが入ってきた時、**この1ファイルを 30分読めば作業開始できる**状態に。

#### 助言 5：「Archeco repo の collaborator にどう？」

**なぜ大事：** Marc が今週リリースした v7.32〜v7.37 を直接読める。学習が加速する。

**私の対応：** YES、即受諾。月曜（6/1）に招待が来る予定。

→ Marc が右側で進化した内容を、左側にも翻訳して取り込めるようになる。

### 5️⃣ Marc が最後にくれた言葉

> 「3つのシステム（宮川・稲井・Marc）は **異なる問題を解いているが、同じ challenge を中心に回っている — 決定を明示化し、伝達可能にすること**」

つまり、3人とも根っこではこれをやっている：
**「個人の頭の中のものを、組織で再利用可能な形に外部化する」**

- 私 → FAM ブランドの暗黙知をシステム化
- 稲井さん → 多人数制作でのブランド忠実度
- Marc → 多サービスの速度と一貫性

これがプロジェクトの **本質** だと再認識した瞬間でした。
