## Q3（先に結論）：写真は Figma に持ってこれる ✅ 実証済

公式 Figma MCP の **`upload_assets`** で、ローカル画像（`/Users/archecoinc./Desktop/Claude_1/Asset/`）を Figma に流し込める。
- フロー：`upload_assets(fileKey, nodeId, scaleMode)` で single-use URL 取得 → `curl -F "file=@xxx.png"` で POST → 指定ノードの塗りに自動設定。
- 本日実証：`Mask group.png`（大前+和田ペア）→ C/B 表 Hero、`【明治】大前写真.png` → 監修者枠 に配置成功。
- 対応形式：PNG / JPG / GIF / WebP（10MB まで）。**SVG 不可**（ロゴ SVG は別途）。
- → **写真は「人間専用」ではなく AI で配置可能**。残るのは「どの写真をどの枠に・どうトリミングするか」の判断 = 指示で渡せる。

## Q1：AI に70%を出させる指示設計

### 核心テーゼ
**AI のアウトプット品質 = 渡した指示（spec / 制約 / 素材）の完成度**。
今回 AI が 3〜4割（ワイヤー）に留まったのは「チラシを作って」と曖昧に投げ、**craft（grid・色ゾーニング・書体ペア・写真処理）が AI の自己流任せ**になったから。craft を**暗黙知のまま渡さず、明示的な入力に変換**すれば 70% に届く。

### レバー1：白紙でなく「型（器）」を渡す（最重要）
ゼロから生成させず、**人力完成型の named slot を埋めさせる**。
grid・色ゾーニング・書体ペア・写真処理が型に内包されている → AI はそれを自動的に継承し、出発点が70%になる。
→ `TEMPLATE-fambox-flyer-v1.md` がその型。次案件は「複製→スロット差し替え」。

### レバー2：ゼロ生成するなら spec に craft を明示的に書く
「セクションを置く」ではなく、以下を**数値・規則で**渡す：
- **グリッド + 実座標**（margin 40 / 2col x40,x310 / 3col x40,x210,x395）
- **色ゾーニング規則**（下記§ゾーニング参照。どの面が何色か＋隣接禁止則）
- **書体ペア + ロール別サイズ**（4書体マップ：Hero=Hiragino 26-30 / 見出し=F910 20 / 本文=F910 10 / 英字=Poppins / 縦書き=YuMincho 32）
- **写真プラン**（どの画像を・どのスロットに・サイズ・CROP/FILL・処理）＋**素材を供給**（Asset フォルダ→upload_assets）
- **ジャンプ率目標**（Hero は本文の約3倍など）

### レバー3：素材と「置く手段」を AI に渡す
実写真が無いレイアウトは何をどうしてもワイヤーに見える（写真は「完成感」の3割）。
→ Asset フォルダを AI に渡し、upload_assets で配置させる。本日それが可能と実証済。

### 結論：理想の指示の形
> プロンプトは散文（「チラシ作って」）ではなく、**「この型の named slot を、この差し替えデータ表と、この Asset マニフェストで埋めよ」** という構造化指示にする。

完成度は指示の完成度に比例する。曖昧な指示=ワイヤー、型+素材+規則=70%。

### 残る「真の人間専用30%」（このツールチェーンでは）
- **ブランド印刷フォント**（Hiragino / F910-Shin-comic-tai / YuMincho）の適用＝MCP 実行環境に未インストールで不可（[[feedback_figma_bridge_text_limitations]]）。Mac 側 1クリック差し替え。
- **最終の美的微調整**（カーニング・写真選定の良し悪し・余白の詰め）。

## ゾーニング分析：なぜ下手に見えたか → 規則

### Before（私の試作）が下手だった理由
1. **全幅フラットな橙ベタ帯を上下に**置き、間は白 → 「サンドイッチ」で単調・重い・リズムなし。
2. **中間ゾーン（ディープブルー）が無い**。色を「装飾」として置き、**情報設計（IA）として使っていない**。
3. 角丸パネルで「囲う」のでなく全面ベタ → 締まりが無い。

### After（本日の修正）
C向け裏面の「お問い合わせ」を**ディープブルーの角丸パネル**としてゾーニング → 役割が一目で分かる面になった。

### ゾーニング規則（型に固定）
| 色 | 役割（この用途以外で使わない）|
|---|---|
| Drive Orange `#FB4C15` | エネルギー/CTA：Hero・クーポン・Instagram のみ |
| Deep Blue `#0F2A5C` | 信頼/連絡：お問い合わせ・法人窓口のみ |
| White / Light gray | エディトリアル本文 |

- **彩度の高い全幅ベタ帯を2つ隣接させない**（必ず白の余白で分離）。
- ゾーンは**角丸パネル（R 8–16）で囲う**、全面ベタは Hero など限定。
- 1色 = 1役割を全ページで一貫。色数を増やさない。

## 指示設計 v2（70% の天井を上げる追補）

v1 の3レバーは「完璧な入力を一発で渡す」前提で、**最も効く要素＝反復ループが抜けていた**。効く順の追補：

### ★最大の改善：一発出力でなく「視覚フィードバックループ」
spec 追従の一発出力は構造的に ~70% で頭打ち。**AI が組む → スクショ → 参照画像と差分自己批評 → 修正**のループが天井を上げる（`get_screenshot` / `node.screenshot()` 保有）。
→ 指示に「**完成後にスクショを撮り、参照画像と比較して差分を3点以上自分で挙げ、直してから出せ**」を入れる。[[feedback_visual_design_video_first]] と同型。

### インプットの質を上げる4点
1. **参照を「描写」でなく「画像」で渡す**：最強の入力は人力サンプルの**レンダリング画像**。「この画像に合わせろ」＋自分の出力と見比べが、どんな散文 spec より効く。→ 本テンプレに各フレーム参照画像を同梱（`reference/` 配下）。
2. **「規則」と「判断(taste)」を分離**：規則化できるもの（grid/ゾーニング/書体スケール）は完全自動化、taste が要るもの（写真選定・トリミング・見出しの強さ）は**人間が事前決定して表に書く**か **AI に2〜3案出させて人間が選ぶ**。AI に taste を黙って推測させない（＝「下手」の発生源）。
3. **コンテンツ表を「完成・検証済」に**：プレースホルダ（`○○% OFF`）・未確定コピー・曖昧な画像名が1つでも入ると穴になって伝播。TBDゼロ・実値・正確なファイルパス・検証済の事実（FAMBOX→FAM BOX）。
4. **負の制約・既存部品・合格基準を同梱**：
   - 負の制約：「Inter 禁止」「彩度高ベタ隣接禁止」「superlative 禁止」（bugs.md DOCTRINE-002/007）
   - 既存部品の再利用指示：「クーポンを描け」でなく「**M-10 を複製して値差し替え**」
   - 合格基準(rubric)を先に渡す → AI が自己採点

### 統合：天井を超えるには
型＝過去の craft の凝縮＝**既知レイアウトの天井 ~70%**。超える／新レイアウト対応には **(a) 型・モジュールライブラリの拡充** ＋ **(b) 参照画像との視覚反復ループの自動化**。
→ Flywheel の伸びしろは「良い spec を書く」より「**型ライブラリ拡充＋視覚批評ループ**」にある。

## Marc kit v7.14 反映（デザイン品質の底上げ）

Marc-Antoine の Archeco kit v7.14（art-direction 層）を解析。**メタ発見：figma-json-pipeline / Generate-Verify / 色引用規律 / Source宣言 / 座標相対 は全て宮川さんの2026-05交換がクレジットされ kit に逆輸入済**。よって「Marc にあって我々に無い」のは技術構造でなく**4点：①スタイルカードの抽象フレーム ②トラッキング/ma の具体数値 ③Words-first ④Refusal 3分類**。

### Top 5 改善（順位）
1. **トラッキング表**（✅ 本日4フレーム108ノードに適用済）：Display40+ -4% / 28-39 -3% / 20-27 -2% / 16-19 -1% / 本文 0 / 小12以下 +1%。「アマチュア感」が消えるゼロコスト最大効果。
2. **Words-first テキスト監査を配置前に**：品質問題の80%は文言。**"premium/最高の/revolutionary" は禁止語**、「ご近所さん(74歳)が言うか」テスト。チラシは文字面積大で直撃。
3. **スコープ付きスタイル宣言**：曖昧な「Editorial×Lab」を正規化 →
   ```yaml
   primary: editorial-premium     # 余白・グリッド・タイポ階層・写真主導を支配
   secondary:
     - bold-geometric  scope: "B向けHero(選手躍動)/numbered step/割引数字"
     - craft-heritage  scope: "監修者紹介/サンクスリボン"
   ```
   C向け=Editorial寄り（家庭・信頼）、B向け=Bold Geometric強め（競技者・エネルギー）。secondary 3つ以上=決定回避。Lab感は別スタイルでなく Editorial の「精度」に内包。
4. **本文幅70-80%＋間(ma)指数スケール**：本文は利用幅の70-80%のみ（現状87%は詰まりすぎ→一段細く）。間は `4/8/16/24/48/80/120/200`、**12/20/32/40 は正当化なしに使うな**。等差y座標を指数リズムへ。
5. **指示テンプレに Source宣言＋構造化spec 5フィールド**：型/Asset manifest/tokens/brand DNA のパスを冒頭宣言→audit-first 強制。手動パースで漏れる5フィールド＝`fills.opacity`（rgbaに焼くな）/`hierarchy.parentId`（フラット配列+depth）/`effects.blendMode`/`variableBindings`/`layout.primaryAxisSizing`。

### その他の移植項目
- **タイポ規律**：見出しに Bold700 禁止（Semibold600 まで）。行間 Display1.05-1.10/見出し1.15-1.25/本文1.50-1.60。
- **アンチパターンは必ず ❌ リスト化**（再利用可能に）：サンセリフのみ/ストック写真/彩度高ベタ2面隣接/全幅サンドイッチ/アイコン塗線混在/本文幅80%超。
- **Refusal 3分類**：絶対（Inter禁止・FAM BOX表記）/条件付き（縦書きYuMinchoは印刷物のみ）/アクセシビリティ可変。
- **アイコンは Lucide 2px に一本化**（Iconify 混在を止める）＋アイコン+ラベル併記。
- **各モジュールに「触OK/触禁止(Forbidden modifications)」2行**を追記し崩れ防止。
- **色語彙**：FAMBOX のオレンジ＋青＝Complementary（補色・単一CTA強調）。彩度は action/signal に予約、surface は静かに（我々のゾーニング規則と一致＝正しい）。
- **写真**：フルブリード or 厳密整列の二択／focal point で切る／ストック写真は本来 ❌（コミッション推奨）。
