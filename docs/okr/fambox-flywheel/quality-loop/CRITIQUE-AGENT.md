# 品質クリティーク・ループ（変革となる学びの仕組み）

> 目的：愚直な「作って直す」を、**測れる採点→具体ギャップ→恒久ルール化**の複利ループに変える。Flywheel の Learn 層の機械化。
> 基準：`.claude/skills/fambox-flyer-builder/references/quality-rubric.md`（9軸/合格80%）。ゴールド見本＝人間仕上げ4枚（同 rubric 参照）。

## ループ全体（1サイクル）
```
Generate（チラシ生成/ブラッシュアップ）
  ↓ get_screenshot
Critique Agent（生成物 × 同面ゴールド × rubric → 採点＋ギャップ）
  ↓ スコア<80% or <5点軸あり
Fix（具体ギャップを修正：写真当て込み/ジャンプ率/ゾーニング/奥行き 等）
  ↓ 再採点（改善幅を記録）
Learn（再発ギャップを bugs.md DOCTRINE / asset-index / taste-and-tokens へ書き戻し）
  ↓
次の Generate は学びが効いた状態で開始＝複利
```
**鍵**：Fix で終わらせず必ず Learn まで回す。ここが「線形改善」と「複利改善」の分岐。

## Critique Agent（subagent / Codex 共通プロンプト）
> 入力：①生成物スクショ ②同面ゴールド見本画像 ③rubric。出力：採点表＋ギャップ＋書き戻し提案（JSON 可）。

```
あなたは FAM BOX 印刷物の品質クリティークです。甘い評価を禁止し、人間仕上げ（ゴールド）を5点の基準にします。

入力:
- 生成物スクショ: <path or nodeId>
- ゴールド見本（同じ面）: <reference/human-X-front.png>
- ルーブリック: .claude/skills/fambox-flyer-builder/references/quality-rubric.md（9軸）

手順:
1. ルーブリックを読む。生成物とゴールドを並べて観察する。
2. 9軸それぞれを 1–5 点で採点。各軸に「測り方」の客観チェック結果を1行で添える（例: 軸1=2点/グレー枠が3つ残置）。
3. 加重スコア（%）を算出。80%未満なら不合格。
4. <5点の軸ごとに「具体ギャップ」と「直す手段」を書く（例: 軸2 ジャンプ率→Hero を 24pt→48pt、Display トラッキング -4%）。
5. 再発しそうな規律は「書き戻し提案」として {対象ファイル, 追記する DOCTRINE/PROC 文} の形で出す。
6. taste 依存（写真選定の良し悪し/カーニング極詰め）は採点せず「人間仕上げ」と明記。

出力フォーマット:
- スコア表（軸/点/チェック結果）
- 加重% と 合否
- 優先修正 Top3（具体手段つき）
- 書き戻し提案（対象ファイル＋文）
変更は提案のみ。ファイルへの自動書込はしない（人間が承認して反映）。
```

### 実行手段
- **Claude**：Agent ツール（subagent_type: brand-voice:quality-assurance 等）にスクショ＋ゴールド＋rubric を渡す。または本セッションで直接採点。
- **Codex**：`codex exec -C <repo> -s read-only "<上記プロンプト>" </dev/null`（採点は読取のみ＝headless でも通る。書込承認の壁を受けない。**`</dev/null` 必須**＝省くと stdin 待ちで停止する 2026-06-09 実証）。

## 2モデルクロス採点（単一モデルの盲点を消す・推奨運用）
> なぜ：同じモデルが「作って・採点」すると盲点が共有され甘くなる。**別モデルで採点**すると別の失敗モードを拾える。今日の rubric にそのまま乗る、最小コスト最高ROIの強化。Claude/Codex は同じ repo・skills・rubric・ゴールドを共有済なので基準は一致する。

### 手順
1. **生成**：Claude または Codex がチラシを作る（生成側を記録）。
2. **二者採点**：同じ {生成物スクショ・同面ゴールド・rubric} を**両モデルで採点**する。
   - Claude 側：本セッション or Agent ツールで採点。
   - Codex 側：`codex exec -C <repo> -s read-only "<Critique プロンプト>" </dev/null`。
   - **採点者は生成者と別モデルを最低1つ含める**（自作自演を避ける）。
3. **突合（reconcile）**：軸ごとに2つのスコアを並べる。
   - **2点以上の乖離がある軸**＝どちらかの盲点 or 基準が曖昧 → 実機 grep / 再観察で裏取りし、必要なら **rubric の「測り方」を鋭くする**（重み・閾値の校正）。
   - **両者一致のギャップ**＝高信頼 → 優先修正＆書き戻し対象。
4. **書き戻しは“合意かつ実機裏取り済”のみ**：片方だけの指摘は採用前に grep/スクショで検証（[[feedback_reviewer_hallucination_check]]：subagent/別モデルは値をハルシネートする → 裏取り必須）。これで DOCTRINE が偏らず頑健になる。

### 記録
- 各サイクルで「生成者 / 採点者2名 / 軸別スコア表（A・B並記）/ 乖離軸 / 合意ギャップ / 書き戻し」を1行ログに残す。乖離の傾向自体が「rubric のどこが曖昧か」の学びになる（メタ複利）。
- 例：`121:8 生成=Codex / 採点=Claude 57%・Codex 55% / 乖離=軸2(±2) → 測り方に「Hero/本文サイズ比」を明記し校正 / 合意ギャップ=写真主導 → DOCTRINE-010`。

## ゲート運用
- **合格80%**未満は「未完成」。スクショだけ撮って報告終了は禁止（DOCTRINE と同精神）。
- 1サイクルごとに「スコア推移」を記録（例: 0608=62% → 修正後 78% → Learn 反映後 次案件 81%）。複利を可視化。
- 重み・閾値は運用しながら校正（v0→v1）。ゴールドが更新されたら基準も更新。

## なぜこれが「変革」か
- 愚直ループ＝信号源だが**主観・散逸・無計測**で線形頭打ち。
- 本ループ＝同じ信号を**客観採点で測り**、**ギャップを恒久ルール化**して**次回に自動適用**。各イテレーションが積み上がる＝70%の天井を構造的に押し上げる。
- 既存資産（rubric/ゴールド/bugs.md/asset-index/DNA）に乗るので新規構築コスト最小。
