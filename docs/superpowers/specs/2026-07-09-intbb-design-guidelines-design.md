# intBB デザイン規約 — 設計ドキュメント

- 日付: 2026-07-09
- 依頼元: 渡辺さん（ARCHECO int グループ / 筑波大学・ARC社員）
- 担当: 宮川
- ステータス: 設計承認済み。渡辺さんからの情報受領待ち（起草はブロック中）

## 1. 目的

intBB（int グループのミニアプリ群プラットフォーム）の全ミニアプリに適用するデザイン規約を作成する。
あわせて intBB フロントエンド（明日=2026-07-10 動作予定）へのデザインフィードバックを別途実施する。

## 2. 想定読者（確定）

**人間＋AI 両対応**の2点セットで納品する:

1. **人間向け規約**（Markdown）— 開発者・デザイナーが読んで守るガイドライン
2. **AI向けルールファイル**（CLAUDE.md / rules 形式）— int チームが Claude 等でミニアプリを
   生成・改修する際にセッションへ読み込ませる規律ファイル

## 3. アーキテクチャ（確定）: 2層分離

### Layer 1: 共通原則層（既存資産から転用）

ブランド非依存の方法論のみを転用する。転用元:

| 転用元 | 転用する内容 |
|---|---|
| ARCHECO UI教材（UIデザインの基本原則 1〜7） | 整数比レイアウト（1:1, 1:2, 2:3）/ 等比スペーシング（1.5x/2x, 等差禁止）/ ジャンプ率によるテイスト制御 / キャラクターライン |
| Design Wheel `docs/design-wheel/` | PATTERN-SCHEMA.md（テイストのパラメータ化・必須/代替可能の区別）/ CRITIQUE-RUBRIC.md（品質判定基準）/ FOUNDATIONS.md |
| FAMBOX DS `brand/fambox/design-system/` | **構造のみ**: tokens 真ソース方式 / Do・Don't カタログ形式 / bugs.md 方式（罠の蓄積と BUG/DOCTRINE/PROCESS 3分類）/ 検証規律（3回失敗ルール・実装後 grep 検証） |

### Layer 2: intBB トークン層（新規抽出）

intBB 固有のブランド定義。渡辺さんの現状フロントエンド＋既存ブランド要素から**抽出**して定義する
（ゼロ候補並べ禁止 = feedback_existing_asset_first 準拠）:

- カラーパレット（Primary / Secondary / Inactive / Error + グレースケール4段階）
- タイポグラフィ（フォントファミリ・6段階スケール・行間・weight ポリシー）
- スペーシングスケール（S/M/L + 比率）
- 角丸・シャドウ・エフェクトのバリアント
- コンポーネント状態表現（Hover / Disabled / Focus 等）

### 禁止事項（DNA汚染防止）

FAM BOX 固有の要素は**転用禁止**: 色 / フォント（Poppins + Hiragino）/ トーン・ボイス。
`project_references_subline` の規律（エフェクト・モーション・レイアウトのみ引用可、色・フォント引用禁止）に従う。

## 4. 渡辺さんへ依頼する情報（返信ドラフト確定版）

1. 現状フロントの全画面スクショまたは画面録画（PC/SP 両方）— 動作後で可
2. 技術スタック（フレームワーク / CSS の書き方: Tailwind, CSS Modules 等）と共通 CSS・共通コンポーネントのコード（リポジトリ閲覧権限でも可）
3. ミニアプリの一覧（現在＋今後の予定）と各アプリの目的・想定ユーザー
4. 既存のブランド要素（ロゴ / 指定色 / 指定フォント / 参考にしたデザイン）
5. ミニアプリ開発で AI コーディング（Claude 等）を使う予定の有無 — AI向けルールファイルの粒度を決めるため
6. Figma デザインファイルがあれば共有

## 5. プロセス（確定）

1. 上記ドラフトで渡辺さんに返信（宮川さんが送信）
2. 情報受領後、2層構成で **intBB デザイン規約 v0.1** を起草
   - 成果物: 人間向け Markdown 規約 + AI向けルールファイルの2点
   - 格納先候補: `docs/intbb/`（起草時に確定）
3. フロント動作後、デザインFBを別途実施（スクショ/録画ベース = feedback_visual_design_video_first 準拠）

## 6. 成功基準

- int チームのメンバー（非デザイナー含む）が規約を読んで、または AI に読ませて、
  ミニアプリの UI を一定品質（Design Wheel でいう非デザイナー70%品質ライン）で作れること
- FAM BOX 固有要素が一切混入していないこと（色・フォント・トーンの grep 検査で確認）

## 7. スコープ外

- intBB フロントエンドの実装作業そのもの
- FAM BOX / Design Wheel 側の資産変更
