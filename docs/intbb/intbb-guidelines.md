# intBB デザイン規約（人間向け）

- version: 0.1-draft（Layer 2 = intBB 固有トークンはフロント情報の受領待ち）
- last_updated: 2026-07-09
- owner: 宮川（ARCHECO）
- 対象: intBB のミニアプリを作る int メンバー（非デザイナー前提・約10名）

---

## 1. この規約の全体像

intBB のデザイン規約は2つのファイルでできています:

| ファイル | 役割 | 読む人 |
|---|---|---|
| **intbb-ai-rules.md** | ルール本体。AI に読ませる | 主に AI（人が読んでもOK） |
| **intbb-guidelines.md**（このファイル） | AI への指示の出し方＋完成チェック | 人間 |

**基本方針: デザインの判断は AI とルールに任せ、人間は「指示」と「チェック」だけやる。**
デザイン知識は不要です。

## 2. ミニアプリ UI の作り方（3ステップ）

### Step 1: AI にルールを読ませる

Claude 等のセッション冒頭で `intbb-ai-rules.md` を読み込ませる（ファイル添付 or 全文貼り付け）。

### Step 2: 要件を伝える（プロンプトレシピ）

以下の型をコピーして埋めるだけ:

```
intbb-ai-rules.md に従って、intBB のミニアプリ画面を作ってください。

- アプリ名: <例: 経費精算ミニアプリ>
- この画面の目的: <ユーザーが何をする画面か1文で>
- 載せる要素: <箇条書き。例: タイトル / 入力フォーム3項目 / 送信ボタン / 履歴一覧>
- 対象デバイス: <PC / SP / 両方>
- 参考にしたい既存ミニアプリ: <あれば名前>
```

**コツ: 見た目の指定（色・大きさ・おしゃれに等）は書かない。** 見た目はルールが決めます。
書くのは「目的」と「載せる要素」だけ。

### Step 3: 完成チェック（1分・5項目）

できあがった画面を見て、以下だけ確認する。全部 YES なら完成:

- [ ] **色**: intBB の色になっているか（他サービスっぽい色が混ざっていないか）
- [ ] **見出し**: 何が一番大事な情報か、パッと見て分かるか
- [ ] **整列**: 要素の端が揃っているか（ガタガタしていないか）
- [ ] **余白**: 詰まりすぎ・空きすぎの場所がないか
- [ ] **ボタン等**: 押せるものが押せそうに見えるか（hover や無効状態があるか）

1つでも NO があれば、AI に「チェックリストの◯番が NG。修正して」と返すだけ。
**自分で直そうとしなくてよい。**

## 3. 困ったとき・ルールが合わないとき

- ルールどおりに作れなかった / ルールが実態に合わない → **⏳ 報告先（Slack チャンネル等）を確定後に記載**
- 報告されたケースは規約の改訂候補として蓄積し、定期レビューで反映します（bugs.md 方式）。

## 4. 規約の更新ルール

- **バージョニング**: v0.x（試行）→ v1.0（正式）。変更はこのファイル冒頭の version と last_updated を更新。
- **承認者**: ⏳ 確定後に記載（規約の変更・例外の最終判断者）
- **レビュー周期**: ⏳ ミニアプリの追加ペース確定後に設定
- **禁止事項（恒久）**: FAM BOX 等、他ブランドの色・フォント・トーンを intBB に持ち込まない。
