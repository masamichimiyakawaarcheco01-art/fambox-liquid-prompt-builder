# intBB AI デザインルール

- version: 0.3（白ベーストークン承認済み 2026-07-10。実装側はこのトークンに合わせて更新する）
- last_updated: 2026-07-10
- owner: 宮川（ARCHECO）
- 方針: **緩めの規約**。作り手の創意を縛らず、intBB としての統一感が壊れる箇所だけ守る。

> **このファイルの使い方**: intBB のミニアプリ UI を Claude 等の AI に作らせるとき、
> 最初にこのファイル全文を読み込ませてから要件を伝える。
> AI は最後に §10 のチェックリストで自己点検してから出力すること。

## 0. 規律レベルの読み方

この規約は「緩め」に設計されている。ルールは3レベルに分かれる:

| レベル | 意味 |
|---|---|
| **[MUST]** | 必ず守る。破ると intBB の統一感が壊れる（4つだけ） |
| **[SHOULD]** | 原則守る。理由があれば逸脱してよい（逸脱は人間に一言伝える） |
| **[FREE]** | 自由。各ミニアプリの個性・作り手の工夫に任せる |

## 1. MUST（これだけは守る・4つ）

1. **色とフォントは §2 のトークンを使う。** 他ブランド（FAM BOX 等）や独自の色・フォントを持ち込まない。
2. **トークン値（§2）を AI が勝手に変更・創作しない。** 未定義の値が必要になったら人間に確認。
3. **押せる要素には最低限の状態を付ける**: default / hover / disabled。フォームは error 表示も。
4. **既存ミニアプリの intBB 移行時は、いきなりリデザインしない**（§9 移行ポリシー参照）。

## 2. intBB トークン（Layer 2 — v0.3 承認済み・白ベース）

> 2026-07-10 渡辺さん承認。方向性=「美しくシンプル・抜け感のある白ベース」。
> **実装がまだ旧配色（ベージュ基調 v0.2）の場合は、このトークンへ寄せる**（適用手順は intbb-ui-feedback-v1.md の P1〜P3）。

### 2-1. Color

| 役割 | 値 | 用途 |
|---|---|---|
| bg | #FAFAFA | 画面背景（ほぼ白） |
| surface | #FFFFFF | カード・サイドバー・入力欄 |
| ink | #1A1C20 | 見出し・本文（ほぼ黒） |
| ink-muted | #9A9AA2 | 説明文・ラベル・非アクティブ |
| primary | #1F3A5F | **アクション専用**: ボタン・アクティブ状態・リンク・ブランドロックアップ |
| accent-gold | #C9A465 | ロゴ・バッジ等の**ごく少量の装飾専用**（面で使わない） |
| line | #ECECEC | ヘアライン罫線・カード境界・チップ枠（区切りは影でなくこれ） |
| note-bg | #F5F5F4 | 案内・警告の面（ベージュ帯にしない） |
| danger | #D14343 | 破壊的アクションの文字色 |

グレースケール: Gray1 #33363D / Gray2 #55585F / Gray3 #9A9AA2 / Gray4 #D9D9DE

**ゾーニング規則 [SHOULD]**: 区切りは「1px line ＋余白」で作り、色帯・影・枠ボックスを増やさない
（**箱を減らす**）。primary の塗りは1画面に1〜2箇所まで。警告・案内は note-bg またはゴーストチップで静かに。

### 2-2. Type

- フォント: 日本語=システムサンセリフ（Hiragino Sans 系）/ 英語=同系
- ジャンプ率: 見出しは**低め**（業務ツールの落ち着き）。ただし**データ数値は大きく**（下記）[SHOULD]
- 6段スケール: 飾り 28px / H1 24px / H2 18px / H3 16px / Body 14px / Small 12px
- **数値表示パターン**: 大きな数字 32–40px（weight 400–500）＋単位は右肩に小さく＋ラベル 11px ink-muted
- 行間: 1.6 前後（最低でもフォントサイズの1:1以上）
- 英字小見出しラベル（ARCHECO / ワークスペース等）: 11px・uppercase・letter-spacing 0.08em・ink-muted

### 2-3. Layout / Components

- 画面型 [SHOULD]:
  - **認証・単機能画面** = 中央1カード型（surface、角丸 20px、line 枠＋微シャドウ1段）
  - **ワークスペース画面** = 3ペイン型（左サイドバー 約260px / 中央 / 右レール。右レールは空なら折りたたみ）
- 角丸: カード 16px / **ボタン・チップ・入力欄=ピル（radius 999px）**
- シャドウ: 原則なし。浮遊要素のみ `0 1px 3px rgba(0,0,0,.06)` の1段。多層シャドウ・グロー禁止 [SHOULD]
- 余白 S/M/L: 12 / 24 / 48（2倍等比）
- プログレスバー: 高さ 4px・ピル・トラック #EEEEEE・フィル primary
- サイドバーのリスト項目は**枠ボックスにしない**: ゴースト（hover #F4F4F5 / 選択 primary 8%＋primary 文字）

### 2-4. Icon

- アイコンは **icons0.dev**（MIT ライセンス・150+ コレクション）から取得する:
  `npx shadcn@latest add @icons0/<collection>/<name>` または SVG コピー。
- コレクションは1つに固定して混在させない（⏳ 線画系を推奨・実装スタックに合わせて確定）[SHOULD]
- サイズは 16 / 20 / 24 の3段・線幅 1.5px 相当で統一 [SHOULD]
- **UI クローム（タブ・ボタン・ナビ・見出し）に絵文字を使わない**。チャット本文・ユーザー生成部は FREE [SHOULD]

> `intbb-ui-feedback-v1.md` を参照。

## 3. 作る順番 [SHOULD]

**①平面構成 → ②余白 → ③整列 → ④タイポ → ⑤色・装飾**。色や装飾から作り始めない。
寸法の決め打ちでなく、要素間の比率でレイアウトを決める。

## 4. 平面構成 [SHOULD]

- レイアウトは単純な整数比（1:1 / 1:2 / 2:3 / 1:3 / Full）で分割する。
- 最も大きなコンテナの分割＝画面の構造設計。まず「どう割れば美しいか」。

## 5. 余白 [SHOULD]

- 等比（1.5倍 or 2倍）で大中小を定義。**等差（10/20/30px 刻み）は避ける**。
- 割り当て: コンテナ↔子=大 / 兄弟間=中 / 要素内=小。迷ったら全部同じ1サイズでも可。

## 6. 整列・タイポ [SHOULD]

- 要素をアラインして「見えない線」を通す。テキストは自動整列後に目視で揃え直す。
- 強調=大きく・ハイコントラスト、補足=小さく・ローコントラスト。
- 6段スケール外のサイズを場当たりで作らない。

## 7. コンポーネント状態 [MUST は §1-3、詳細は SHOULD]

- フォーム: focus（枠=primary）/ 入力後 / error（danger 枠＋メッセージ）。
- ダイアログのボタン2つは「キャンセル=弱（アウトライン）/ 実行=強（primary 塗り）」。
- 選択: 複数=チェックボックス / 排他1択=ラジオ / ON-OFF=トグル。

## 8. ミニアプリ頻出パターン（組織知シートから転記）[SHOULD]

移行予定のミニアプリはダッシュボード・レポート系が多い。以下は AI-PJ 組織知の確定ルール:

- **ダッシュボードのタブは「ユーザー × 目的 × 更新頻度」の3軸で分ける**（経営/月次 と マーケ/週次 を同居させない）。
- 各タブ冒頭に「このタブのユーザーと目的」を1行明記する。
- 更新頻度の異なる指標を同一画面に置く場合、**各指標に更新頻度・最終更新日（可能なら更新責任者）を明示**する。
- UI を作る前に指標定義（名称/定義/ロジック/データソース）が揃っているか確認し、無ければ人間に確認する。

## 9. 既存ミニアプリの移行ポリシー [MUST]

既存ミニアプリは各担当が作り込んだデザイン資産。intBB 移行時は:

1. **第1段階（移行時）**: レイアウト・構成はそのまま。色とフォントだけ §2 トークンに寄せる（それも困難なら現状維持で可）。
2. **第2段階（任意・改修時）**: 画面を触る機会があれば SHOULD ルールに寄せていく。
3. **強制リデザインはしない。** 統一より「動き続けること・作り手の意欲」を優先する。

## 10. 出力前チェックリスト（AI が自己点検）

- [ ] 色・フォントは §2 トークン内か（他ブランド色の混入なし）
- [ ] ⚠️暫定値を勝手に確定・変更していないか
- [ ] 押せる要素に default / hover / disabled があるか（フォームは error も）
- [ ] レイアウトは整数比 / 余白は等比か（SHOULD・逸脱時は一言添える)
- [ ] タイポは6段スケール内 / ジャンプ率低めか
- [ ] ダッシュボード系ならタブ3軸・更新頻度明示（§8）を満たすか
- [ ] 既存アプリの移行なら §9 に従っているか（勝手にリデザインしていないか）
