# スキル陳腐化リスク棚卸し — AIエージェント時代対応

## 目的

[尾原Ep1](obara-ai-agent-era-ep1.md) と [Chesky動画](chesky-airbnb-ai-era-redesign.md) の警告：
> 経験で培ったスキル・実行力が **無効化されるリスク**

これを **自分の業務に即して** 棚卸し、価値の源泉を「実行」から「設計・判断・関係性」へシフトする計画を作る。

## 分類軸

| カテゴリ | 説明 | アクション |
|---|---|---|
| 🔴 高リスク | 1-2年で陳腐化、AIで代替可能 | **委譲・自動化** を急ぐ |
| 🟡 中リスク | 3-5年で陳腐化、部分自動化済 | **設計側に立ち位置を移す** |
| 🟢 低リスク | 当面は人間が必要 | **継続+深化** |
| ⭐ 価値増大 | AI時代に **価値が高まる** | **時間を増やす** |

## 3. 高リスク業務の移行計画

### A. 手書きLiquid実装 / 個別レイアウト調整
**現状**: Figmaデザインを見て、手でLiquidを書く / 既存セクションを微調整する
**移行先**: LPB v4 を **Human-on-the-Loop** で運用 → 自分は **デザイントークン設計** と **承認** に集中
**P0アクション**: LPB v4 に自動テスト1本追加（次ファイル参照）

### B. FAMBOX OKR 週次レポート作成
**現状**: 木曜17時に手動で実績集計 → 須藤さん共有用レポート生成
**移行先**: GA4 / Shopify Admin / 各種KPIソースから **自動集計 → ドラフト生成** → 人間が物語化部分のみ追記
**移行ステップ**:
1. KPIのデータソース API一覧化
2. データ取得スクリプト（Python）作成
3. ドラフト生成プロンプト整備
4. 週次自動実行 + Slack通知

### C. インタビュー文字起こし
**現状**: 動画/音声を手作業で文字に
**移行先**: Whisper API or 既存サービスで自動化（Otter.ai, Notta等）
**P0アクション**: 守屋選手撮影前に文字起こしツール選定

### D. 営業チラシ・SNS素材の編集
**現状**: 1案ずつデザイン
**移行先**: テンプレート + 可変パラメータ → AIが **バリエーション自動生成**（ポジション別/チーム別）
**移行ステップ**:
1. テンプレートを変数化（選手名・ポジション・チーム・キャッチコピー）
2. 1案を作って **生成ルール** に蒸留
3. AIで複数バリエーション展開 → 自分は選別・調整のみ

### E. GA4 数値手動チェック
**現状**: 毎週ダッシュボードを目視
**移行先**: 異常検知ルール → アラート時のみ人間が確認
**P0アクション**: 「異常とは何か」の定義を文書化

### F. Excel/Spreadsheet集計
**現状**: 手動でデータをコピペ・関数で集計
**移行先**: BigQuery + 定期実行クエリ + 自動ダッシュボード
**注**: projects/analytics で既に着手中

## 4. ⭐ 価値増領域への時間シフト計画

「実行」から「設計・判断・関係性」へ。**3ヶ月で時間配分を変える**：

| 領域 | 現状の時間 | 目標 |
|---|---|---|
| 戦略・判断（OKR・優先度・「言わせたい結論」） | 10% | **25%** |
| ブランドDNA・設計言語の体系化 | 5% | **15%** |
| ガードレール設計（LPB・FAMBOX運営） | 0% | **15%** |
| クライアント関係・戦略提案 | 15% | **20%** |
| 手作業実装（Liquid・レイアウト） | 40% | **15%** ← 大幅削減 |
| 集計・レポート | 15% | **5%** ← 自動化 |
| その他（MTG・移行・調査） | 15% | 5% |

## 6. やめるべき思考

| ❌ 古い前提 | ✅ 新しい前提 |
|---|---|
| 「自分で全部やった方が早い」 | 「設計してAIに任せた方が長期的に早い」 |
| 「クライアントは実装の対価を払う」 | 「クライアントは設計・判断の対価を払う」 |
| 「営業時間は手を動かす時間」 | 「営業時間は判断・関係性の時間」 |
| 「品質は最後に自分でチェック」 | 「品質はガードレールで自動保証」 |
| 「個人デザイナーは小回りが利く」 | 「個人デザイナーは多エージェント統合者」 |
