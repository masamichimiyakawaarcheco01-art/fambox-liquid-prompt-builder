# GA4 異常検知ルールの拡張

## 現状

`projects/analytics/alert_check.py` が既に存在：
- 日次データから異常値を検知
- アラートログシートに記録
- Slack Webhook URL があれば通知

## 何を拡張するか

「**異常検知のみ → 異常検知 + 改善案ドラフト + 検証提案**」へ進化（System of Action 化）。

| 現状 | 拡張後 |
|---|---|
| 「セッションが急減しました」 | 「セッションが急減しました。原因仮説3つ、検証手順、暫定対応案を生成しました」 |
| 人間がアラートを見て調査開始 | AIが調査仮説を立てた上でアラートする |
| 静的な閾値（前日比 ±X%） | 季節性 + トレンドを考慮した動的閾値 |

## 異常検知ルールの体系化

### 検知レイヤー（多層化）

| Layer | 内容 | 既存 |
|---|---|---|
| **L1: 静的閾値** | 前日比 ±30%、目標値の80%未満 | ✅ alert_check.py |
| **L2: 統計的検知** | 移動平均 ±2σ から外れる | ⏳ 拡張 |
| **L3: 季節性検知** | 曜日・月パターンから外れる | ⏳ 拡張 |
| **L4: 仮説生成** | 異常時に Claude API で原因仮説を生成 | ⏳ 新規 |

### 監視対象指標（FAMBOX用）

| 指標 | 重要度 | L1閾値 | L2 (σ) | アラート先 |
|---|---|---|---|---|
| GA4 セッション | 高 | 前週比-30% | 2σ | Slack #fambox-analytics |
| GA4 ユーザー | 高 | 前週比-30% | 2σ | 同上 |
| 注文数 | 最高 | 前週比-50% | 2σ | 即時通知 |
| 売上 | 最高 | 前週比-40% | 2σ | 即時通知 |
| GSC 検索クリック | 高 | 前週比-50% | 2σ | Slack |
| GSC 検索表示 | 中 | 前週比-50% | 2σ | Slack |
| お問い合わせ数 | 中 | 0件×3日連続 | 2σ | Slack |
| 直帰率 | 中 | +20%pt | 2σ | Slack |
| カート追加率 | 中 | 前週比-30% | 2σ | Slack |
| CV率 | 高 | 前週比-30% | 2σ | Slack |

## 仮説生成プロンプト（L4 拡張）

```
FAMBOX のGA4データで以下の異常が検知されました。

【検知内容】
- 指標: {metric_name}
- 期間: {date}
- 観測値: {actual_value}
- 期待値（移動平均）: {expected_value}
- 偏差: {sigma}σ

【補助データ（過去14日）】
{daily_trend}

【参考: 直近の主要施策】
{recent_actions}

【出力】
1. **原因仮説（3つ）**: 確率高い順に並べる
2. **検証手順**: 各仮説を確認するための具体的アクション
3. **暫定対応案**: 即座にやるべき緩和策（あれば）
4. **追加データ要求**: 判断に必要な追加情報

【制約】
- 「分かりません」は禁止。仮説は必ず3つ出す
- 数値根拠を明記する
- FAMBOXコンテキスト（スポーツ栄養・食事サブスク）を考慮
```

## 実装ステップ

### Step 1: 統計的検知（L2）追加
`alert_check.py` に統計関数を追加：
- 14日移動平均と標準偏差を計算
- 観測値が ±2σ 外なら検知
- 既存の静的閾値と組み合わせ（OR条件）

### Step 2: 季節性検知（L3）追加
- 曜日別・月別の平均を別シートに保持
- 当日値と該当曜日/月の平均を比較
- 例：「日曜の通常セッション 100 → 今日 20 = 異常」

### Step 3: 仮説生成（L4）追加
- 異常検知時に Claude API を呼ぶ
- 直近14日のトレンドデータを添えて仮説生成
- Slack通知に仮説を含める

### Step 4: 多経路通知
- 重要度に応じて通知方法を分ける：
  - 最高（売上・注文）: Slack DM + Email
  - 高: Slack channel
  - 中: アラートシートのみ（Slackは日次サマリ）

## 通知メッセージの設計

### Before（現状）
```
🚨 [FAM Analytics] 異常検知
2026-05-14: セッション数 25（前日比 -68%）
```

### After（L4 拡張後）
```
🚨 [FAM Analytics] 異常検知 + 原因仮説

【検知】2026-05-14: GA4セッション 25（前週同曜日比 -78%、3σ外）

【原因仮説（確率順）】
1️⃣ GSCのインデックス変動 — 前週も検索表示-72%。L4 (50%)
   → 検証: Search Console > インデックス カバレッジを確認
2️⃣ サイト障害 — 14:00以降に急減。L3 (30%)
   → 検証: Shopify ストアの稼働状況、エラーログ確認
3️⃣ 競合キャンペーン開始 — 同業の動向。L2 (20%)
   → 検証: 直接競合のSNS・LP更新確認

【暫定対応案】
- GSC不安定の場合: インデックス再申請、サイトマップ再送信

【リンク】
- GA4 ダッシュボード: <URL>
- Search Console: <URL>
- アラートログ: <URL>
```

## ガードレール

- **アラート疲れ防止**: 同一指標で連続発火する場合は2回目以降を抑制
- **誤検知防止**: 「データ取得失敗 = 異常」とならないように。データソース側のエラーは別経路で通知
- **コスト管理**: 仮説生成（Claude API）は1日あたり最大20回まで
- **L4 のみで判断しない**: 必ず人間が検証する前提のため、仮説に「（仮説）」明記
