## Slide 3 / 20 — なぜ「いま」なのか

# AIは「考える道具」から「動く仕組み」へ

| 旧 | 新 |
|---|---|
| System of Intelligence | **System of Action** |
| 意思決定支援 | 自律実行 + 学習ループ |
| 人が判断 → AIが手伝う | AIが判断・実行 → 人がガバナンス監督 |

→ さらにその先 — **Human-in-the-Lead**：人間は目的・倫理・文脈の設定のみ

> **話すこと**: Google Cloud Next26 と Adobe Summit 2026 で示された潮流。
> 半年でGoogleコードのAI生成比率が50%→75%。生産性6倍。
> 「Human-in-the-Lead」はEp2で示された最終形態 — これが目指す未来形です。

出典: 尾原和啓「グーグルとアドビの衝撃デモ」「アドビが提唱するブランド知能」（Business Insider Japan）

## Slide 4 / 20 — 2つの衝撃事例

# 衝撃の数字（実例）

**Case 1: 物流（ホルムズ海峡封鎖シナリオ）**
- 人間アナリスト: **72時間**
- AIエージェント: **3秒**（86,400倍）

**Case 2: ブランドキャンペーン（Ulta Beauty）**
- 深夜のバズ検知 → キャンペーン構築: **5分**
- バズから収益化まで: **15分**
- 従来: 翌朝以降 + 数日

> **話すこと**: 物流もマーケも同じ構造です。
> 「人手で点と点を結ぶ速度」がビジネスの上限を決めている。
> FAMBOXも同じ。食材変動、SNSの動き、アスリート個別要求 — 全部が制約条件の組み合わせ。

## Slide 5 / 20 — FAMBOXの現状

# FAMBOXの現在地

**動かしている価値**:
- 科学的根拠に基づくスポーツ栄養
- アスリートを対等の挑戦者として扱う
- 「次の一歩」のための燃料

**動かす速度の上限**:
- 食材供給の変動 → 手動でメニュー再構成
- 顧客個別最適化 → 個別対応で属人化

> **話すこと**: FAMBOXの強みは変わりません。科学・リスペクト・燃料。
> ただし、運営の速度が手作業で決まっているのが現状です。
> ここを突破します。

## Slide 6 / 20 — 構想

# Experience Flywheel + 5エージェント

FAMBOXを **4段階のフライホイール** として動かす。
各段階を担う **5つのAIエージェント** が、文脈を守りながら自律実行する。

```
       ┌─→ Sense（感知）─────────┐
       │   在庫モニター + 異常検知       │
       │                                ↓
   Run（学習）                  Generate（生成）
   反応データから              栄養計算 +
   プレーブック更新            メニュー組み立て
       ↑                                │
       │                                ↓
       └─── Reach（実行）───────────────┘
           配送最適化 + 顧客通知
```

オーケストレーター = 4段階を束ねる統合役
人間 = ループの外で **目的・倫理・文脈** を設定

> **話すこと**: 大事なのは「機能の積み上げ」ではなく「ループが回り続ける」こと。
> 1周回るごとに学習が深まり、FAMBOX独自の最適化が積み重なります。

## Slide 7 / 20 — Sense（感知）

# Sense — 感知

**動かす範囲**: 環境監視・微細シグナル発見

| 担当エージェント | 検知対象 |
|---|---|
| **在庫モニター** | 仕入先API・倉庫データ・賞味期限・需要予測 |
| **異常検知 + 仮説生成** | GA4・売上・問合せ・SNS反応の異常 |
| **顧客嗜好** | 継続率の低下兆候・嗜好変化のシグナル |

**人間が握る**: 仕入先の追加・変更判断 / 大規模インシデント時のエスカレーション

> **話すこと**: フライホイールの起点。
> 「兆しを掴む速度」がそのまま「次に踏み出す速度」になります。

---

## Slide 8 / 20 — Generate（生成）

# Generate — 生成

**動かす範囲**: ガードレール内で自動解決策を生成

| 担当エージェント | 生成内容 |
|---|---|
| **栄養計算** | PFCバランス・必要栄養量・代替食材の数千通り組み合わせ |
| **メニュー組み立て**（栄養計算と統合） | アスリート別・競技別・季節別の最適メニュー |
| **コンテンツ生成**（オプション） | SNS・記事ドラフトの自動生成 |

**人間が握る**: 栄養基準の決定（栄養士監修）、アレルギー対応ルール、ブランドトーン

> **話すこと**: 人手では到底追いつかない組み合わせ探索。
> ただし「FAMBOXらしさ」のガードレール内で動きます — 次のスライド以降で詳述します。

---

## Slide 9 / 20 — Reach（実行）

# Reach — 実行

**動かす範囲**: AI同士の連携による実行

| 担当エージェント | 実行内容 |
|---|---|
| **配送最適化** | 全配送先の一括ルート計算・冷蔵管理・配達タイミング |
| **顧客通知** | パーソナライズメール・SNS応答・CRM自動化 |
| **オーケストレーター** | 全エージェント間の整合性確保 |

**人間が握る**: 配送パートナーとの関係維持 / 顧客との直接対話

参考: Manhattan Associates の自動倉庫が同等の運用を既に実装中。

> **話すこと**: 「実行」段階で AIが自律的に動きます。
> ただし関係性の領域（人対人）は人間が握り続けます。

---

## Slide 10 / 20 — Run（学習）

# Run — 学習

**動かす範囲**: 顧客反応データの取得と学習 → 次のループに反映

| 学習対象 | 取得元 |
|---|---|
| **継続率パターン** | 顧客嗜好エージェントの蓄積データ |
| **離脱要因** | 解約理由 + 直前の体験データ |
| **新ペルソナ発見** | 異常検知が示した「想定外の挙動」 |
| **プレーブック更新** | 例外事例から自動でルール候補生成 |

**人間が握る**: 新ルール採用 / 棄却の最終判断

> **話すこと**: ここが本当の差別化です。
> 1周回るごとに **FAMBOX独自の最適化** が積み重なる。他社では再現できない資産になります。

## Slide 11 / 20 — オーケストレーター（統合の例）

# 統合の例: 食材断絶への即時対応

```
[Sense] 在庫モニターが鶏胸肉の入荷停止を検知
   ↓
[Generate] 栄養計算が代替食材で同等PFCのメニューを生成
   ↓
[Generate] 顧客嗜好で各顧客の許容範囲に絞り込み
   ↓
[Reach] 配送最適化が既存配送計画への影響を再計算
   ↓
[Reach] 顧客通知が「明日のメニュー変更」を個別送信
   ↓
[Run] 顧客反応を回収 → 次回の代替案精度を上げる
   ↓
[人間] 重大なら最終承認、通常なら事後レビューのみ
```

総処理時間: **3秒〜数十秒**（人手では数時間〜数日）。

> **話すこと**: これが Experience Flywheel の真価です。
> 1つ1つの機能ではなく、全体が連動して動きます。

## Slide 14 / 20 — Decision Trace（着手済）

# 修正履歴が「らしさ」を育てる

**Decision Trace 機構** — Adobe「ブランド知能」の実装手法

宮川さんが日々行う「ここはNG / OK / 修正」を **構造化保存** →
N件蓄積したら共通パターン抽出 → **新ルール候補** を自動提示。

```
[AI生成] → [宮川さん判断] → [理由タグ付き保存]
                ↓

                ↓

                ↓
        [採用 → ガードレール強化]
```

## Slide 15 / 20 — Human-in-the-Lead

# 「全任せ」ではない、「Human-in-the-Lead」

| 段階 | 人間の役割 |
|---|---|
| Human-in-the-Loop（旧） | ループ内で判断・実行 |
| Human-on-the-Loop（Phase 1-2） | ループ外で監督 |
| **Human-in-the-Lead（Phase 3+）** | **目的・倫理・文脈の設定のみ** |

**Phase 3+ 後の須藤さん・宮川さんの役割**:
- 🎯 **目的設定** — FAMBOXは何のために動くか
- ⚖️ **倫理基準** — 何をしてはいけないか（アレルギー・誇大広告・契約違反）
- 📚 **文脈設定** — どの背景で動くか（ブランド・組織のコンテキスト）

それ以外はフライホイールが回す。

> **話すこと**: 人手不要にする話ではありません。
> 人間の時間を「設計・判断・関係性」に集中させる構想です。

## Slide 16 / 20 — ガードレール（致命的領域は必ず人間）

# 致命的領域は必ず人間が握る

| 自動でやる | 必ず人間が判断 |
|---|---|
| 在庫モニター・栄養計算・通常配送 | **アレルギー誤配送ゼロの確認** |
| 異常検知・仮説生成・通常通知 | **重大インシデント時のエスカレーション** |
| 通常時のメニュー組み立て | **季節キャンペーン・新商品の方針** |
| 文脈学習・プレーブック更新 | **新ルール採用 / 棄却** |

**安全弁の原則**:
1. 致命的領域（アレルギー・契約・財務）は必ず人間
2. ガードレールは事前にFAMBOX運営チームが設計
3. AIの自律行動は **ログ化・遡及可能** に（Decision Trace）

> **話すこと**: ガードレールは「事後チェック」ではなく「事前構造」です。
> Adobe Summit 2026 で示された通り、システム自体に NG を出さない構造を作ります。

## Slide 17 / 20 — Phase 1: Quick Win

# Phase 1（最初の3ヶ月）

## Sense層から始める

**選定エージェント**: 在庫モニター + 異常検知エージェントの最小版

**選定理由**:
- フライホイールの **起点（Sense）** を最初に確立する
- 効果が **見えやすい**（食材ロス削減 / 機会損失防止）
- 致命的領域に踏み込まない（人間判断を残せる）
- 学習効果が大（次フェーズへの転用知見）

**目標**:
- 月間食材ロス: 現状値の **-30%**
- 入荷遅延の検知時間: 24時間 → **1時間**
- 異常検知から仮説提示までのリードタイム: **5分以内**
- 運営チームの在庫確認作業: 週5h → **週1h**

> **話すこと**: 一気に5エージェントは作りません。
> フライホイールの「Sense」を確立してから、Generate → Reach → Run へ拡張していきます。

# 付録: 用語集（質疑対応用）

| 用語 | 意味 |
|---|---|
| System of Action | 自律実行型のAIシステム。意思決定支援（System of Intelligence）の次世代 |
| Experience Flywheel | Sense→Generate→Reach→Run の自動学習ループ（Adobe Summit 2026） |
| Human-in-the-Loop | AIのループ内で人間が判断・実行する旧型 |

| Brand Intelligence | 企業の暗黙的特性（トーン・配色・らしさ）をAIに学習させる仕組み |
| Decision Trace | 修正履歴の構造化保存。プレーブック自動構築の素材 |
| マルチエージェント | 複数のAIエージェントが協調して動く構成 |
| オーケストレーター | エージェント群を束ねる統合役 |
| ガードレール | AI自律行動の安全弁。事前定義のルール |
