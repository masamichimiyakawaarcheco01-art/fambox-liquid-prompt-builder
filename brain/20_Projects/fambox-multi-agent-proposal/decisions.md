# 意思決定ログ

## 2026-05-15: 提案の構造を「Phase段階導入」に決定

**決定**: 5エージェント全実装ではなく、Phase 1（在庫モニター）から段階導入する構造で提案する。

**根拠**:
- いきなり大規模実装は **クライアントの心理的ハードルが高い**（数百万円規模の投資判断）
- Phase 1 で価値を見せてから Phase 2-3 へ進む方が **降りる選択肢を残せる**
- Brian Chesky の Project Hawaii 手法（小規模精鋭から始めて横展開）に整合

**代替案**:
- 5エージェントを一気に提案 → 拒否されるリスク高
- ホルムズ海峡並みの実装提案 → スケール感が合わない

**採用しない理由**: 段階導入の方が双方の合意形成コストが低い。

---

## 2026-05-15: Phase 1 候補に「在庫モニター」を選定

**決定**: Phase 1 のエージェントは **在庫モニター** とする。

**比較した候補**:

| 候補 | 効果見える化 | 致命度 | 実装難度 | 学習効果 |
|---|---|---|---|---|
| **在庫モニター** ✅採用 | ◎ | 低 | 中 | 高 |
| 異常検知（仮説生成） | ○ | 低 | 中 | 高 |
| 栄養計算 | △ | 中 | 高 | 中 |
| 顧客嗜好 | △ | 低 | 高 | 中 |
| 配送最適化 | ○ | 中 | 高 | 低 |

**採用理由**:
- 食材ロス削減 = **数値で見える**
- アレルギー判定等の **致命的領域に踏み込まない**
- 仕入先APIとの連携が **既存業務の延長線上**
- ここで得た知見が他エージェントに **転用可能**

## 2026-05-15: トーンは「FAMBOX Verbal Guideline」厳守に

**決定**: 提案資料は FAMBOX Verbal Identity Guideline v1.0 に厳密準拠する。

**根拠**:
- 須藤さんに「これはFAMBOX自身の言葉だ」と感じてもらうため
- 外注の提案ではなく、内部からの構想として受け取ってもらうため
- ARCHECO が長期パートナーであることの証明

**実装**:
- NG語（サポート / 寄り添う / 応援 / 〜かもしれません / 頑張る等）不使用
- Verb Bank 使用（突破する / 動かす / 踏み出す / 燃やす）
- キーワード16語のうち推進系を中心に
- 断定する語尾

## 2026-05-15: ROI試算は「仮置き値」で構造のみ提示

**決定**: ROI試算の実数値は提示せず、構造と算出方法のみを提示する。

**根拠**:
- FAMBOX の実数値（月間食材ロス・機会損失・継続率等）は ARCHECO 側で精緻に把握していない
- 仮の数値で提案すると **議論が数値の妥当性に集中** してしまう
- 提案の本質（構造的に投資回収可能）が伝われば十分

**フロー**:
1. 提案 → 合意
2. 詳細フェーズで FAMBOX から実数値提供
3. ROI 確定 → Phase 1 詳細見積もり

## 2026-05-21: LLMO層を統合（v3 候補化）

**決定**: 提案デッキ v2 に LLMO（テキスト側 Brand Intelligence）を統合層として追加する。

**根拠**:
- 尾原Ep2 で示された Brand Intelligence は視覚側だけでなく **テキスト側にも必要**
- AI関連ボットがHTMLリクエストの 4.2% を占有（Cloudflare 2026）
- ARCHECOには既に Verbal Identity v1.0 + 修正履歴蓄積基盤がある → **9割の素材は揃っている**
- LPB v4 に LLMO Check API を実装済（2026-05-21）→ **技術的に即運用可能**

**実装**:
- 6番目のエージェント「LLMO 監査」を Run層に位置付け
- 既存ブログ上位3記事のリライト を Phase 1 と並行
- Verbal Identity v1.1（LLMO拡張）を運用開始
- 詳細: [llmo-integration.md](llmo-integration.md)

**代替案**:
- LLMO を Phase 2 以降に後送り → 機会損失（AI流量増加トレンド）
- 採用しない理由: 既に実装基盤があり、Phase 1 と並行運用のコストが低い

## 2026-05-21: ハーネスエンジニアリングフレーミングで v4 化

**決定**: 提案デッキを v4 として再パッケージ。**「ハーネスエンジニアリング 5層構造」を上位概念** に据え、5+1 エージェント・Experience Flywheel・LLMO はその実装として再配置。

**根拠**:
- 2026-03-24 公開の Qiita 記事「ハーネスエンジニアリング入門」（@nogataka）で、ARCHECO が3年積み上げてきた仕組みに **正式名称が付いた**
- 散在していた概念（System of Action / Brand Intelligence / Vibe Coding / LLMO / Decision Trace）が **「ハーネス」の5層** で完全統合される
- FAMBOX × ハーネス完成度は既に **65%**（ルール95 / スキル80 / フック20 / メモリ90 / フィードバック40）→ 競合参入障壁を数字で示せる
- Phase 1 着手位置を「完成度の低い2層（フック+フィードバック）から始める」と説明できる → 機能的選定理由より説得力が高い
- ARCHECO の業態定義を「Web 制作」から **「AI 制御アーキテクト」** へ進化させる根拠になる
- 長期パートナーシップの構造的根拠（ハーネス運用は単発外注では不可能）

**v3 → v4 の主な変更**:
| 項目 | v3 | v4 |
|---|---|---|
| 上位概念 | Experience Flywheel + 5+1 エージェント | **ハーネスエンジニアリング 5層** |
| Phase 1 着手 | Sense 層から | **フック層 + フィードバック層 同時着手** |
| 競合優位性 | ブランド・インテリジェンス素材 9 割 | **ハーネス完成度 65% / 残りフック+フィードバックのみ** |
| ARCHECO 業態定義 | 言及なし | **AI 制御アーキテクトへ進化（Slide 19）** |
| ロードマップ表記 | フライホイール完成度 25% → 100% | **ハーネス完成度 75% → 100%**（既に65%は揃っている） |

**成果物**:
- [proposal-deck-v4.md](proposal-deck-v4.md) — 20 スライド
- [executive-summary-v4.md](executive-summary-v4.md) — 1ページサマリ
- v2/v3 は参照用として保存

**代替案**:
- v3 で提案を続行 → ハーネスという統合概念を失う、業態定義の進化を提示できない
- 採用しない理由: v4 の方が ARCHECO の戦略的位置づけ強化に直結する
